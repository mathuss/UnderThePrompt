# Verification notes: UTP-20261105-03 (OpenSSH musl/Alpine password bypass)
Checked 2026-11-05.

| Claim in script | Source | What the source says |
|---|---|---|
| Fixed 2026-11-05; Alpine advisory + OpenSSH 10.6p2 | [Alpine advisory](https://alpinelinux.org/posts/2026-11-05-openssh-password-authentication-bypass/), [OpenSSH release notes](https://www.openssh.org/releasenotes.html#10.6p2) | Advisory dated 2026-11-05; 10.6p2 released 2026-11-05. |
| Affects musl + PAM disabled | OpenSSH release notes | "Linux systems that use the musl libc and PAM disabled". |
| Key-only / passwordless accounts store `*` | Alpine advisory | Accounts with a `*` field: root (default since ~3.16), key-only users, directory users, `alpine` user in tiny-cloud images. |
| Without PAM, sshd hashes with crypt() and compares to the shadow field | Alpine advisory | Stated. |
| musl crypt() returns `*` as error for keys over 256 bytes | Alpine advisory; [sshhole.com](https://sshhole.com) | Both state it. |
| Conditions: non-PAM sshd (or UsePAM no), PasswordAuthentication yes (default), an account with `*`, another with `$5$`/`$6$` hash | Alpine advisory | Stated as all required. |
| Fix: `apk upgrade -U -a`, restart sshd (running daemon keeps old code); or `PasswordAuthentication no`; check logs | Alpine advisory | Stated. |
| In-browser simulation exists, runs locally | sshhole.com | Simulated Debian (glibc) vs Alpine (musl) boxes in the browser. |
| Researcher | OpenSSH notes + advisory + sshhole | Özgün Kültekin, Wakefield. |

Not used: musl's 2012 change history (only on sshhole.com, not needed); OpenWrt/Buildroot/Yocto exposure (only on sshhole.com, not confirmed by those projects).
