# The password that was too long / La contraseña demasiado larga

## Why now
On 2026-11-05 Alpine Linux published an advisory and OpenSSH shipped 10.6p2 to fix a password-authentication bypass on Linux systems that use the musl C library with PAM disabled (Alpine is the big one). It was #1 on Hacker News the same day. The cause is a great "under the hood" story: two layers each doing something reasonable, and an asterisk that means two different things.

## Notes for the Producer
- **Responsible framing:** this is a patched, publicly disclosed bug. The video explains the cause and the fix; it must not show an attack against any real host, and it doesn't give a step-by-step. The only "attack" visual is the researcher's own in-browser simulation and labeled schematics.
- No CVE was assigned at the time of the advisory. Re-check on production day; if one exists, add it to the on-screen source card.
- Don't say "all Linux" or "all OpenSSH": only musl-based systems with PAM disabled (Alpine is the main one; the write-up also names OpenWrt, Buildroot and Yocto, but the script only names Alpine, which the advisory confirms).
- `root` on Alpine is only reachable if `PermitRootLogin yes`; the script avoids implying root was always exposed.
- Pronunciation: "musl" (MUS-el), "sshd" (S-S-H-D), "crypt" (kript). ES: "ese-ese-hache-de".
- If Docker is installed later, a real Alpine container capture of the check/upgrade commands would raise the visual score.
