# The padlock keys that were one byte long / Las llaves del candadito que medían un byte

## Why now
On 2026-11-09 Apple shipped macOS 27.2.1 (plus 26.7.3 and 15.8.3), closing the last gap on Macs: command-line tools like curl and git still trusted eight compromised eMudhra intermediate certificates whose private keys anyone could recover. The disclosure site updated its timeline and client tests on 2026-11-10. The original story (2026-10-20) was one of the biggest security threads of the autumn on Hacker News (1,281 points, plus 1,202 for "Apple's git still trusts the compromised eMudhra certificates"). It has a free, no-login test that shows whether your own browser still trusts the bad keys.

## Sources
- [Apple: About the compromised eMudhra intermediate CAs](https://support.apple.com/en-us/149555): eight intermediates compromised, six TLS; "could create certificates that appear valid for any website"; blocked in Safari, Mail and Apple frameworks via automatic configuration updates; "Starting in macOS 27.2.1, these command-line tools stop accepting these certificates" (also 26.7.3, 15.8.3); manual cert.pem workaround. Published 2026-11-09. Checked 2026-11-15.
- [Apple security releases](https://support.apple.com/en-us/100100): macOS Golden Gate 27.2.1, Tahoe 26.7.3, Sequoia 15.8.3, all 2026-11-09. Checked 2026-11-15.
- [We have a problem (eMudhra)](https://emudhra.we-have-a-problem.com/): timeline, test hosts, Android and Windows steps, Electron note (patched Electron 44.9.1, 43.8.1, 42.11.16). Dated 2026-10-20, updated 2026-11-10. Checked 2026-11-15.
- [Scott Helme, Eight Bits of Trust](https://scotthelme.co.uk/eight-bits-of-trust-emudhras-ca-keys-cracked-in-milliseconds/): single-byte P-384 private keys, milliseconds to recover, browser block timing, July 2039 expiry. 2026-10-20. Checked 2026-11-15.
- [eMudhra press release](https://emudhra.com/en/press-release/emudhra-to-exit-global-ssl-tls-certificate-business): exit from global SSL/TLS; "no data was breached". 2026-10-22. Checked 2026-11-15.

## Notes for the Producer
- Pronunciation: eMudhra = "ee-MOOD-rah". Scott Helme = "HELM".
- Credit: say "Scott Helme" on screen when his post is shown; the test site is by Dennis Jackson and contributors (credit on the end card and in the description). The original reporter is only named "Wayne"; don't invent a surname.
- The test: open `https://dv-g3b-emudhra.we-have-a-problem.com/` in the capture browser. The site warns that a ✅/error only means "the connection failed", so a network problem looks the same. Record it on a working connection and say "error = protected", nothing stronger. Never click through the warning on camera.
- "Chrome and Firefox the day of the report" = 17 Oct (Chrome CRLSet that evening, Firefox OneCRL hours later per Helme; the site lists both on 17 Oct). Microsoft 20 Oct, Apple 22 Oct (site timeline). Apple's own note doesn't give the October date.
- eMudhra's position, if a line is wanted: it says its "infrastructure was not compromised and no data was breached". The other sources say the keys were generated incorrectly. Both can be true; don't say eMudhra was hacked.
- Don't claim iOS needed or got a fix: Apple's note covers macOS only. Don't claim an attack in the wild: no source says these keys were used against anyone.
- Android: most devices got the block through Google Play services (site). Only mention the manual "Trusted credentials" route as "the test site has steps", because disabling AAA Certificate Services can break some sites.
- Overlap: UTP-20261112-01 (Chrome zero-day) is also "update your browser". Don't schedule them back to back.
