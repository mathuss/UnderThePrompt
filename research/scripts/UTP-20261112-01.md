# Chrome is under attack: the one-click fix / A Chrome lo están atacando: el arreglo de un clic

## Why now
On 2026-11-09 Google shipped Chrome 157.0.8103.50/.51 with nine security fixes and said an exploit for one of them, CVE-2026-125350 (use after free in XML), "exists in the wild". CISA added it to its Known Exploited Vulnerabilities catalog on 2026-11-10, and Microsoft confirmed the same exploit for Edge. A second Chrome update on 2026-11-11 (157.0.8103.78/.79) fixed 83 more bugs. Everyone has a Chromium browser, and the fix does nothing until the browser is relaunched.

## Notes for the Producer
- Re-check the version on production day: Chrome ships security updates almost weekly. Say "X or higher" with the then-current stable number, and re-read the newest Chrome Releases post in case another exploited bug was added.
- "Brave, others" on screen: CISA says only "Chromium-based browsers". Don't claim a fixed version for Brave, Opera or Vivaldi unless their own release notes are opened. For Edge, only the Android build (157.0.4341.53) was seen naming this CVE on 2026-11-12; check the desktop entry before showing a version.
- Press calls this the eighth exploited Chrome zero-day of 2026 (The Hacker News, Qualys). Google's post doesn't give a count, and The Hacker News page returned 403, so the count is **not** in the script.
- The memory animation is a schematic and must be labeled. Google has published no technical detail; don't draw anything more specific than "freed memory gets reused".
- The KEV text says code execution "inside the sandbox": don't say the attacker takes over the computer.
- If Chrome on the capture PC is already up to date, the About page shows "Chrome is up to date" with no Relaunch button; show that instead and say so.
- Overlap check: no other queued script covers Chrome.
